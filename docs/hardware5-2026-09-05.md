## Native multicore fault: concrete addressing defect

The native photos show a general-protection fault at `IRQ_TIMER+0x006B` after
AP startup, while another CPU was reading startup files from USB storage.
It is not simply a slow compiler load.

Disassembly of hardware4's ISO kernel shows:

```
IRQ_TIMER+0x5D: mov eax,0x5c70       ; &dev, but only the module-relative offset
IRQ_TIMER+0x62: mov edx,0xfee000b0   ; LAPIC_EOI
IRQ_TIMER+0x67: mov rax,[rax+0x10]  ; supposed dev.uncached_alias
IRQ_TIMER+0x6B: mov dword [rdx+rax],0
```

There is no absolute or import relocation for this `&dev` immediate in the
ZXE patch table. INT_WAKE has the same pattern. Reading an unrelated low-memory
value as the alias can produce an invalid EOI address. This matches the fault
instruction and is a strong cause candidate; native verification remains needed.

The narrow correction avoids changing the compiler: IntPICInit publishes a
runtime EOI pointer into an assembler-labelled slot after UncachedAliasAlloc,
before IntInit2 installs the handlers and before starting APs. INT_WAKE and
the AP branch of IRQ_TIMER load that slot using label-relative addressing.
INT_WAKE preserves its only changed register, RAX. Core 0's timer path is
unchanged. The removed Mac mini single-core guard remains removed.

`utils/check_irq_eoi.py` is a read-only gate for the emitted kernel: it checks
both RIP-relative slot loads, the 32-bit EOI stores and INT_WAKE's RAX/IRETQ
sequence. Run it on the newly built kernel before publishing another ISO.
It rejects hardware4 as expected. It does not verify native APIC operation.

## Installed boot source changes

- VMInstallDrive no longer emits the install CD's port as a required T: mount.
  MountAHCIAuto still discovers optical drives that are present. The existing
  function argument is retained for compatibility.
- AHCIPortInit throws a mount error for an unavailable port signature instead
  of entering the debugger. Existing callers can handle the failed mount and
  continue using an available boot disk. Device-type mismatch checks remain.
- These source changes do not retrofit the already compiled UTM kernel.
- The late final Limine configuration write is documented above but not yet
  refactored: safely moving it earlier needs explicit compile-success handling,
  rather than merely checking for a kernel file copied from the live ISO.

## Pointer/browser work remains separate

No pointer or browser fix is included in this candidate yet. UTM's configured
USB3 option still places its built-in HID devices on the legacy EHCI bus;
virt-manager's test uses xHCI. Preserve both paths and PS/2 compatibility.

Two items to investigate without treating them as established causes:

- EHCI tablet report parsing and absolute coordinates versus mouse_hard scaling
  and relative reports; use the actual HID descriptors and report bytes.
- BrowserBoot uses relative `Cd("Programs/Zinc")` after conditionally loading
  Net. If the stack is already loaded, it does not first select `~/Net`.
  Launchers also set de.net_up without verifying the ZincV3 symbol. Reproduce
  with a startup error log before expanding the browser fix.
